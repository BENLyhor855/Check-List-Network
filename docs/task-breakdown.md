# Task breakdown

The checklist and site record are the usable first version. The tasks below are proposed follow-up work, not completed features or GitHub issues. Priorities can change once the intended environment is confirmed.

| Priority | Task | Done when |
| --- | --- | --- |
| 1 | Pilot the checklist on one authorized small site or a lab | A reviewer has completed the record, identified ambiguous or missing checks, and documented changes without publishing site data. |
| 2 | Tailor scope and acceptance criteria | The owner has confirmed target environments, required segments, test points, thresholds, and which optional checks apply. |
| 3 | Add a worked, fictional example | An example shows a complete test, a denied flow, an exception, and a handover decision using non-sensitive invented data. |
| 4 | Expand recovery guidance | An approved example explains backup verification, restore prerequisites, rollback triggers, and evidence for an appropriate test window. |
| 5 | Consider automation | Repeated checks are identified from the pilot, with input format, permissions, safe execution boundaries, and expected output agreed before code is added. |

When proposing a change, include its purpose, applicable environment, verification method, and any assumptions. Keep real inventories, addresses, credentials, and configuration exports outside the public repository.
